# Переход на Platega (my.platega.io)

## Что уже сделано в коде

- Автооплата вынесена в диспетчер **`payments.py`** — бот и сайт больше не зависят от конкретной платёжки.
  Провайдер переключается настройкой `payment_provider` в базе (`off` / `aipay` / `platega`).
- Создан модуль **`platega.py`** по официальной документации Platega (docs.platega.io):
  - создание платежа: `POST https://api.platega.io/transaction/process` (заголовки `X-MerchantId`, `X-Secret`);
  - проверка статуса: `GET https://api.platega.io/transaction/{id}`;
  - приёмник callback (вебхука): `POST /webhook/platega` в `web_app.py` (проверяет заголовки X-MerchantId/X-Secret).
- Сейчас провайдер = **`off`**, поэтому:
  - на сайте в окне оплаты кнопка «⚡️ Оплатить картой (авто)» скрыта (осталась ручная оплата по чеку);
  - в боте в выборе способа оплаты — только «📥 Запрос реквизитов»;
  - серверные защитные проверки тоже стоят: даже прямой вызов API вернёт «временно недоступна».
- Старый AiPay-код (`aipay.py`, вебхук `/webhook/aipay`, ключ в админке) **не удалён** — вернуть его можно
  в один клик переключателем провайдера в админке.

## Что сделать, когда ответит менеджер Platega

1. **Взять у менеджера / в ЛК my.platega.io (страница «Настройки»):**
   - `MerchantId` (UUID) и `Secret` (API-ключ);
   - **ID метода оплаты** для карты/СБП (в примерах доков: `2` = СБП QR, `13` = крипта);
   - уточнить, обязательно ли `metadata.userId` для вашего магазина (мы передаём всегда, хуже не будет);
   - подтвердить хост API: по докам `api.platega.io` (если не заработает — спросить, не `app.platega.io` ли).

2. **В Telegram-боте: `/admin` → ⚙️ Настройки бота:**
   - «🆔 Platega Merchant ID» → ввести UUID;
   - «🔑 Platega Secret» → ввести ключ;
   - «🧾 Platega ID метода» → ввести число (например 2), если отличается от дефолтного;
   - «🔁 Автооплата» → переключить на **Platega**. Кнопка автооплаты сама появится на сайте и в боте.

3. **В ЛК Platega → Настройки → Callback URLs** указать:
   ```
   https://amneziawg.fun/webhook/platega
   ```
   (HTTPS с валидным сертификатом уже есть на новом сервере.)

4. **Тест:** купить самый дешёвый тариф через сайт/бота → оплатить → проверить, что доступ выдался
   автоматически (или что пришёл callback; смотреть `journalctl -u vpn_bot -f`).

## Установка на сервер (деплой)

На новом сервере (192600, 78.17.66.215) код раскладывался вручную через FileZilla, поэтому
залейте эти изменённые файлы в `/root/vpn_bot/` и перезапустите сервис:

```
platega.py          (новый)
payments.py         (новый)
web_app.py
user_handlers.py
admin_panel.py
database.py
templates/dashboard.html
```

```bash
systemctl restart vpn_bot
journalctl -u vpn_bot -n 20 --no-pager
```

Откат, если что-то пойдёт не так: в админке переключить провайдер обратно на `off` (платежи снова
только вручную) — ничего перезапускать не нужно.

## Остался вопрос к менеджеру (для 100% уверенности)

- Точный формат статуса в ответе `GET /transaction/{id}` и в callback: код ожидает строки
  `PENDING` / `CONFIRMED` / `CANCELED` (и обрабатывает `CHARGEBACKED`, `FAILED`, `EXPIRED`).
  Документация подтверждает эти значения, но перепроверить по письму менеджера стоит.
