# Подключение Platega

## Что есть в проекте

- `payments.py` — единый платёжный модуль сайта и Telegram-бота. Провайдер: `off`, `platega` или `aipay`.
- `platega.py` — создание ссылки, проверка статуса и авторизация callback по `X-MerchantId` / `X-Secret`.
- **Веб-админка → Настройки (`/admin/web/settings`) → «Автооплата · Platega»** — отдельная форма с подсказками. Поля есть даже в новой базе.
- **Бот → `/admin` → «⚙️ Настройки бота»** — те же настройки и явный выбор провайдера.
- `POST /webhook/platega` — публичный приёмник уведомлений сервиса, не требующий входа на сайт. Без правильных ключей уведомление отклоняется.
- При подтверждении сверяются сумма в RUB и ID заказа. Повторный callback или одновременная проверка оплаты не выдают доступ повторно.
- Новый заказ запоминает своего провайдера: его можно проверить после переключения системы или выключения новых автоплатежей. Ручная оплата не удалена.

**Важные исправления заготовки:** API использует `https://app.platega.io`, а не `api.platega.io`; для режима `auto` поддерживается API v2 и поле ссылки `url`. Числовые методы используют API с заданным методом и поле `redirect`.

## Что получить у Platega

Создайте/подключите магазин в [личном кабинете Platega](https://my.platega.io) и согласуйте с менеджером:

1. **Merchant ID** — UUID магазина для заголовка `X-MerchantId`.
2. **Secret / API-ключ** — секретный ключ для `X-Secret`.
3. Какие способы оплаты включены у магазина, их лимиты и минимальную сумму.
4. Если нужен фиксированный способ — его числовой `paymentMethod`.

Merchant ID и Secret выдаёт менеджер при подключении; они также доступны в ЛК на странице «Настройки».
Это **не** токен Telegram-бота, не ваш Telegram ID и не номер банковской карты.
Не присылайте Secret в чат и не добавляйте его в исходники.

## Что вписать в веб-админке

Откройте `/admin/web/settings` под аккаунтом администратора. В блоке **«Автооплата · Platega»**:

| Поле | Что вписать |
|---|---|
| Провайдер автооплаты | **Platega** — включить; **Выключена** — пока только ручная оплата. Без обязательных настроек включение будет отклонено. |
| Merchant ID (`platega_merchant_id`) | UUID вашего магазина из ЛК Platega, без кавычек и пробелов. |
| Secret / API-ключ (`platega_secret`) | Секретный API-ключ этого же магазина, без кавычек и переносов строк. |
| Способ оплаты (`platega_payment_method`) | **`auto` — рекомендуется:** покупатель выбирает из подключённых способов на странице Platega. **`2` — СБП / QR.** Другой ID используйте только по указанию менеджера; например, `13` предназначен для криптоплатежей, если они подключены. |
| Публичный HTTPS-адрес сайта (`site_url`) | Адрес **вашего** сайта: например, `https://amneziawg.fun`. Не адрес API Platega. Без `/dashboard`, параметров и данных авторизации. |

Нажмите **«Сохранить настройки оплаты»**. Настройки сохраняются вместе, одной транзакцией; при ошибке в форме прежние значения остаются нетронутыми.

Merchant ID и Secret не подставляются в HTML страницы. Чтобы заменить их, введите новые значения.
**Пустые поля оставляют ранее сохранённые значения**, а не удаляют их.
Статус «настройки заполнены» проверяет формат, но не подтверждает правильность ключей или доступность способов у вашего магазина.

На новой базе метод по умолчанию — `auto`, автооплата выключена. На существующей базе сохранённый метод (в том числе `2`) и ключи автоматически не меняются.

## Что вписать в личном кабинете Platega

В веб-админке ниже формы есть готовое поле **Callback URL**.
Скопируйте его в **Platega → Настройки → Callback URLs**, в URL уведомлений об изменении статуса транзакции.

Если ваш сайт — `https://amneziawg.fun`, адрес будет:

```text
https://amneziawg.fun/webhook/platega
```

Если домен другой, используйте:

```text
https://ВАШ-ДОМЕН/webhook/platega
```

- URL должен быть доступен извне по HTTPS с действующим сертификатом.
- Reverse proxy (например nginx) должен передавать `POST /webhook/platega` приложению, не блокируя заголовки `X-MerchantId` и `X-Secret`.
- Вход/сессионные cookie для callback не нужны. Нельзя закрывать этот маршрут авторизацией nginx или проверкой браузерной CAPTCHA.
- После смены домена сохраните новый `site_url` и обновите callback в ЛК Platega: сохранение в нашей админке **не меняет настройки в Platega**.

Адрес возврата после успешной/неуспешной оплаты приложение передаёт само: `https://ВАШ-ДОМЕН/dashboard`.
**Возврат в кабинет не подтверждает оплату** — доступ выдаётся только по авторизованному callback или проверке статуса через API.
Без callback доступ при закрытом кабинете/боте не будет выдан автоматически: пользователю понадобится проверка статуса.

## Настройка через Telegram

`/admin` → **⚙️ Настройки бота**:

1. **🆔 Platega Merchant ID** → UUID магазина.
2. **🔑 Platega Secret** → API-ключ. Бот по возможности удаляет сообщение с введённым ключом.
3. **🧾 Platega метод (auto / ID)** → `auto` или согласованный числовой ID.
4. **🌐 Адрес сайта** → публичный HTTPS-адрес.
5. Скопируйте показанный **Callback URL** в ЛК Platega.
6. **💳 Выбрать провайдера автооплаты** → **Platega**.

Доступ к Telegram-админке — у главного администратора из `config.ADMIN_ID`; веб-админка также поддерживает дополнительных администраторов.
Изменения настроек после обновления кода применяются без перезапуска приложения.

## Обновление сервера и проверка

Изменения в репозитории не означают, что они уже установлены на вашем рабочем сервере.
Перед обновлением сделайте резервную копию `vpn_database.db` и локальных секретных файлов.
При ручной загрузке обновите как минимум:

```text
platega.py
payments.py
database.py
web_admin.py
admin_panel.py
web_app.py
user_handlers.py
templates/admin_settings.html
templates/dashboard.html
```

Перезапустите существующий сервис:

```bash
systemctl restart vpn_bot
journalctl -u vpn_bot -n 50 --no-pager
```

При старте миграция добавит недостающие поля настроек и колонку провайдера заказа, не удаляя прежние ключи и заказы.

После настройки:

1. Создайте платёж с сайта или из бота на сумму **в пределах лимитов магазина**.
2. Проверьте переход на страницу Platega и оплатите.
3. Проверьте автоматическую выдачу/продление подписки, скачивание конфига и уведомление администратору.
4. Проверьте кнопку статуса в боте/опрос в кабинете. Повторная проверка не должна снова продлевать подписку.

Реальные платежи требуют ваших ключей, подключённого магазина и доступного callback. Автотесты используют подменённые API/SSH/Telegram и не списывают деньги:

```bash
python3 -m venv .venv
.venv/bin/python -m pip install -r requirements-dev.txt
.venv/bin/python -m pytest tests -q
```

При ошибке API 401/403 проверьте пару Merchant ID / Secret. При HTTP 400 уточните у менеджера доступность способа и лимиты суммы.
Если оплата подтверждена, но SSH/выдача доступа не удалась, callback отправляет предупреждение администратору: исправьте причину и выдайте доступ вручную. Возврат/chargeback уже оплаченного заказа не отзывает подписку автоматически — требуется отдельная обработка администратором.

Откат: выберите **«Выключена»** в провайдере. Новые автоматические платежи скроются, ручная оплата останется.
Не удаляйте ключи, пока есть незавершённые платежи. Заказы, созданные **до** миграции, не имеют записанного провайдера и проверяются по текущей настройке, как раньше: завершите их перед сменой системы.
Ключи хранятся в локальной SQLite-базе; ограничьте доступ к базе и резервным копиям. `.gitignore` исключает базу, `config_tokens.py` и секрет сессии из Git.
