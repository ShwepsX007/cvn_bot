# Перенос cvn_bot: 2.57.243.151 → 78.17.66.215

## Что представляет из себя проект (по коду)

Один процесс `web_app.py`, который одновременно тянет:
- **веб-сайт** — FastAPI + uvicorn на `0.0.0.0:8000` (последняя строка `web_app.py`);
- **Telegram-бота** — aiogram-поллинг запускается в том же процессе (`startup_event`);
- **планировщик** APScheduler (уведомления об истечении, очистка триалов и т.д.).

Состояние, которое живёт ВНЕ кода и обязано переехать:
- `vpn_database.db` (SQLite в папке проекта) — пользователи, подписки, заказы, серверы,
  настройки (`aipay_api_key`, `manual_payment_details`, `site_url`);
- `.session_secret` — секрет cookie веб-входа (если потерять, всех разлогинит на сайте);
- `/root/.ssh/` — ключ, которым бот ходит по SSH на VPN-ноды (`ssh_manager.py` вызывает
  `/usr/bin/ssh` без `-i`, т.е. используются дефолтные ключи `id_rsa`/`id_ed25519` из `/root/.ssh`).

Снаружи завязаны на домен `amneziawg.fun`:
- nginx проксирует домен на порт приложения;
- вход через Telegram-виджет (домен один раз задан в BotFather `/setdomain` — менять не надо);
- вебхук AiPay `https://amneziawg.fun/webhook/aipay` (в кабинете AiPay менять не надо,
  меняется только IP за доменом).

## Три реальных конфликта и их решения

1. **Порт 8000 уже занят** соседним проектом на новом сервере.
   Решение: запустить бота на **8001** через `uvicorn web_app:app --port 8001`
   (код трогать не нужно), а в новом server-блоке nginx проксировать
   `amneziawg.fun → 127.0.0.1:8001`.
   ⚠️ Нельзя запускать `python web_app.py` — там жёстко прописан порт 8000
   (последняя строка файла), процесс упадёт или будет конфликтовать.

2. **Общий `/root/.ssh` с соседним проектом.** Папку ЦЕЛИКОМ копировать нельзя.
   - `authorized_keys` — только **дописывать** (иначе затрёте доступы соседнего проекта
     и, возможно, свои собственные);
   - пару ключей бота (`id_*` + `id_*.pub`) — скопировать ОБЯЗАТЕЛЬНО: все VPN-ноды
     уже доверяют этому публичному ключу, тогда ноды трогать не придётся;
   - `known_hosts` — НЕ копировать: бот ходит с `StrictHostKeyChecking=no`, файл сам
     заполнится; зато чужой `known_hosts` может дать конфликт отпечатков и сломать
     ssh-подключения соседнего проекта;
   - `config` (если есть на старом) — НЕ копировать вслепую: `/root/.ssh/config`
     читается ВСЕМИБ ssh-вызовами на сервере, включая соседний проект.
   - `authorized_keys`, лежащий ВНУТРИ папки какого-то проекта (не в `/root/.ssh`) —
     инертен: sshd читает только `/root/.ssh/authorized_keys`. Такой файл можно
     переносить свободно, ни на что не повлияет.

3. **Домен всё ещё смотрит на старый сервер** (проверено: `amneziawg.fun → 2.57.243.151`),
   поэтому сайт отдаёт 502 от nginx старого сервера. В конце меняем A-запись
   на `78.17.66.215`.

Плюс: **поллинг бота должен быть ровно один**. Сначала останавливаем сервис на старом
сервере, потом поднимаем на новом. Иначе два процесса подерутся за апдейты Telegram.

## Пошаговый план

### Шаг 0. Старый сервер: остановить бота, ничего больше не трогать

```bash
# на 2.57.243.151
systemctl list-units --type=service | grep -iE 'vpn|bot'   # как называется юнит
systemctl stop  <имя-сервиса>
systemctl disable <имя-сервиса>        # чтобы не ожил после перезагрузки
ps aux | grep -E 'web_app|uvicorn' | grep -v grep   # убедиться, что процесса нет
```

Остановка ДО копирования обязательна — иначе можно снять `vpn_database.db` в момент
записи и унести битый файл. Сайт и так уже отдаёт 502, даунтайм не увеличится.

### Шаг 1. Скопировать проект на новый сервер

С нового сервера (78.17.66.215):

```bash
rsync -av --exclude 'venv' --exclude '__pycache__' \
  root@2.57.243.151:/root/vpn_bot/ /root/vpn_bot/
```

Проверить, что главное доехало:

```bash
ls -la /root/vpn_bot/vpn_database.db /root/vpn_bot/.session_secret
```

Размеры должны совпадать со старым сервером. Если путь к проекту на старом сервере
другой — подставьте его (посмотреть: `systemctl show <сервис> -p WorkingDirectory`).

### Шаг 2. Аккуратно разобрать SSH-ключи

Посмотреть, что уже есть на новом сервере:

```bash
ls -la /root/.ssh/          # на 78.17.66.215
ls -la /root/.ssh/          # на 2.57.243.151 (какая пара ключей у бота: id_rsa? id_ed25519?)
```

**2.1. Смержить authorized_keys (не перезаписать!):**

```bash
# на новом сервере
ssh root@2.57.243.151 cat /root/.ssh/authorized_keys >> /root/.ssh/authorized_keys
sort -u /root/.ssh/authorized_keys -o /root/.ssh/authorized_keys
chmod 600 /root/.ssh/authorized_keys
```

**2.2. Скопировать пару ключей бота** (пример для `id_ed25519`; подставьте имя из шага 2):

```bash
scp -p root@2.57.243.151:/root/.ssh/id_ed25519 root@2.57.243.151:/root/.ssh/id_ed25519.pub /root/.ssh/
chmod 700 /root/.ssh
chmod 600 /root/.ssh/id_ed25519
chmod 644 /root/.ssh/id_ed25519.pub
```

Если файл с таким именем на новом сервере УЖЕ есть (это ключ соседнего проекта —
не трогать его!), скопируйте ключ бота под отдельным именем:

```bash
scp -p root@2.57.243.151:/root/.ssh/id_ed25519 /root/.ssh/vpn_bot_key
scp -p root@2.57.243.151:/root/.ssh/id_ed25519.pub /root/.ssh/vpn_bot_key.pub
chmod 600 /root/.ssh/vpn_bot_key
```

и укажите его для VPN-нод в `/root/.ssh/config`:

```bash
# список нод из базы:
python3 - <<'EOF'
import sqlite3
for ip, port in sqlite3.connect('/root/vpn_bot/vpn_database.db').execute(
        "SELECT ip, port FROM servers WHERE active=1"):
    print(ip, port)
EOF

cat >> /root/.ssh/config <<'EOF'
Host <IP_НОДЫ_1> <IP_НОДЫ_2>
    IdentityFile /root/.ssh/vpn_bot_key
    IdentitiesOnly yes
EOF
chmod 600 /root/.ssh/config
```

(Порт ssh указывать не надо — `ssh_manager.py` передаёт `-p` из базы сам.)

**2.3. Проверить доступ бота к каждой ноде:**

```bash
ssh -p 2222 root@<IP_НОДЫ> 'docker ps --format "{{.Names}}" | grep amnezia'
```

Должно вывести `amnezia-awg2`. Обратите внимание: по вашим инструкциям 78.17.66.215
сам является VPN-нодой (контейнер `amnezia-awg2`, sshd на 2222). Если эта нода есть
в таблице `servers`, бот будет ходить по SSH сам на себя — это нормально, просто
убедитесь, что ключ бота добавился в собственный `authorized_keys` (п. 2.1 это покрывает),
и проверьте, какой порт ноды записан в базе (22 или 2222).

### Шаг 4. systemd-юнит на порту 8001

`/etc/systemd/system/vpn_bot.service`:

```ini
[Unit]
Description=CVN VPN bot + web app (amneziawg.fun)
After=network-online.target
Wants=network-online.target

[Service]
WorkingDirectory=/root/vpn_bot
ExecStart=/root/vpn_bot/venv/bin/uvicorn web_app:app --host 127.0.0.1 --port 8001
Restart=always
RestartSec=5

[Install]
WantedBy=multi-user.target
```

```bash
systemctl daemon-reload
systemctl enable --now vpn_bot
journalctl -u vpn_bot -f          # должно быть "WebApp, Telegram-бот и Планировщик ... запущены"
curl -I http://127.0.0.1:8001/    # ждём 200
```

Порт 8001 выбран только потому, что 8000 занят соседним проектом. Соседа это не трогает.

### Шаг 5. nginx для amneziawg.fun

`/etc/nginx/sites-available/amneziawg.fun`:

```nginx
server {
    listen 80;
    server_name amneziawg.fun www.amneziawg.fun;

    client_max_body_size 20m;   # загрузка чеков на /web/receipt

    location / {
        proxy_pass http://127.0.0.1:8001;
        proxy_set_header Host $host;
        proxy_set_header X-Real-IP $remote_addr;          # ВАЖНО: по нему антифрод триалов
        proxy_set_header X-Forwarded-For $proxy_add_x_forwarded_for;
        proxy_set_header X-Forwarded-Proto $scheme;
    }
}
```

```bash
ln -s /etc/nginx/sites-available/amneziawg.fun /etc/nginx/sites-enabled/
nginx -t && systemctl reload nginx
```

`X-Real-IP` обязателен: `web_app.py` берёт его для ограничения «1 триал на 12 часов с IP».

### Шаг 6. Переключить домен и выпустить SSL

Менять что-либо в BotFather (`/setdomain`) и в кабинете AiPay (webhook URL) **не нужно** —
домен не меняется.

## Ответы на конкретные опасения

**«Не затрёт ли переносимый проект чужой authorized_keys?»**
Затрёт — только если скопировать `/root/.ssh` целиком поверх существующего.
При переносе по пункту 2 (дописывание, а не замена) оба проекта уживаются:
`authorized_keys` — общий список «кому можно входить», в нём просто живут ключи
обоих проектов рядом.

**«Повлияют ли остальные файлы из папки ssh переносимого проекта?»**
- `known_hosts` — не копировать (может мешать, боту не нужен);
- `config` — не копировать вслепую (влияет на все ssh-вызовы на сервере);
- приватный/публичный ключ бота — копировать обязательно (ради него всё и затевается);
- `authorized_keys` внутри папки проекта (не в `/root/.ssh`) — ни на что не влияет,
  это просто файл данных.

**«Что делать с портом 8000?»**
Ничего не отбирать у соседа: бот работает на 8001, наружу смотрит только через
свой server-блок nginx. Главное — не запускать `python web_app.py` напрямую.
