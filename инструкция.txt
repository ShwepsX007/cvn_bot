ИНСТРУКЦИЯ: подготовка НОВОГО сервера сервиса к подключению к боту — простыми словами
===================================================================================

Почему всё именно так: сервер бота не может подключаться к «двери» SSH №22 —
у ЕГО хостера закрыт выход на внешний 22-й порт. Поэтому мы договорились
стучаться в дверь №2222, и на каждом новом сервере её нужно один раз открыть.

СЛОВАРИК:
  Порт          — номер «двери» на сервере (1..65535). SSH = дверь 22 (мы
                  добавим 2222), трафик ваших клиентов = дверь вида 40158.
  TCP           — «по бумажкам», для команд и входа (SSH).
  UDP           — «на голос», для данных подключенных устройств (трафик клиентов бежит быстрее).
  Firewall      — охранник на входе у хостера: двери нет в его списке = не пускает.
  0.0.0.0/0     — «все адреса интернета». В поле «источник» = впускать с любого IP.

Шаги 1–4 делаются один раз на новом VPS; 5–7 — уже через мастер.

ШАГ 1. Купите VPS: тариф Ubuntu 22.04 или 24.04, виртуализация KVM.
       Сохраните IP (напр. 45.12.34.56) и root-пароль.

ШАГ 2. Проверьте дверь 2222 у «охранника» хостера.
       В ВЕБ-ПАНЕЛИ хостера найдите раздел «Firewall / Файрвол / Сеть»
       (если такого раздела нет — всё и так открыто, шаг пропускаем).
       Добавьте правило:
           протокол = TCP
           порт     = 2222
           источник = 0.0.0.0/0        (пускать всех)
       Читается так: «пускать всех в дверь 2222 обычными письмами».

ШАГ 3. Откройте дверь 2222 на САМОМ сервере
       (команды — в VNC/веб-консоли хостера, чёрный экран терминала).

       Узнать вариант:  systemctl status ssh.socket --no-pager

       a) увидели слово «active» → Ubuntu 24.04, команды целиком:
           mkdir -p /etc/systemd/system/ssh.socket.d
           cat > /etc/systemd/system/ssh.socket.d/listen.conf <<'EOF'
           [Socket]
           ListenStream=
           ListenStream=0.0.0.0:22
           ListenStream=0.0.0.0:2222
           EOF
           systemctl daemon-reload
           systemctl restart ssh.socket

          # ВАЖНО: именно 0.0.0.0:22 — это «слушать для IPv4». Без этого
          # бывает слушатель только на IPv6 ([::] в ss) и бот не достукится.

       b) написало «not found» → Ubuntu 22.04, одна команда:
           echo -e "Port 22\nPort 2222" >> /etc/ssh/sshd_config && systemctl restart ssh

       Проверка обязательно:  ss -tlnp | grep sshd
           → должны быть ДВЕ строки: порт 22 И порт 2222.
       И с компьютера:  ssh root@ВАШ-IP -p 2222  → пускает.

ШАГ 4. Поставьте Amnezia через официальное приложение (на своём компьютере —
       с него дверь 22 доступна, всё честно):
       приложение → «+» → «У меня есть данные доступа» (или «Добавить сервер»)
       → IP, порт 22, логин root, пароль → выбрать AmneziaWG → «Установить».
       2–5 минут. Затем создайте в приложении тестового клиента, скачайте
       конфиг и проверьте, что подключение устанавливается — контейнер
       amnezia-awg2 жив, всё готово к мастеру.

ШАГ 5. Мастер (админка → Серверы → 🚀): IP, SSH-порт 2222, root-пароль.
       Мастер докинет SSH-ключ бота, проверит (при необходимости подремонтирует)
       контейнер, зальёт add_user.sh/remove_user.sh, занесёт сервер в продажу.

ШАГ 6. Откройте дверь для трафика клиентов.
       Мастер в конце журнала покажет «внешний UDP-порт: 40158» (номер у вас свой).
       Вернитесь в ТОТ ЖЕ раздел Firewall (шаг 2) и добавьте правило:
           протокол = UDP  (⚠️ не TCP!)
           порт     = тот, что назвал мастер
           источник = 0.0.0.0/0
       Забыли шаг — устройства подключатся, но передача данных не будет работать.

ШАГ 7. Проверка через бота: «Клиенты» → тестовый доступ на этот сервер →
       конфиг в AmneziaWG на телефоне → включить. Сайты открываются — готово.


РАСПОЗНАВАНИЕ ПРОБЛЕМ
---------------------
timed out на подключении
  → В мастере указан не 2222, или в панели хостера TCP 2222 не открыт для всех.
  → Исходящий 22 закрыт на стороне бота НАВСЕГДА — порт 22 в мастере не использовать.
unable to connect к 2222
  → sshd на 2222 не слушает: шаг 3 не выполнен (или VPS переустановили — тогда
    слетают и sshd_config, и dropin ssh.socket: повторите шаг 3 заново).
  → Проверьте ss -tlnp | grep sshd: если порты висят на [::] (только IPv6) —
    перемените listen.conf на вариант с 0.0.0.0: из шага 3a.
REMOTE HOST IDENTIFICATION HAS CHANGED
  → Норма после переустановки VPS (host-ключи новые). С ПК:
        ssh-keygen -R <IP>
        ssh-keygen -R "[<IP>]:2222"
    затем ssh снова → ответить yes.
контейнер «is restarting», логи пустые
  → сломан «заводской» контейнер хостера: удалите и поставьте Amnezia
    приложением (шаг 4) — или дайте мастеру авто-ремонт.
мастер завершил ✅, но сервис не гоняет трафик
  → забыли шаг 6: UDP-порт не открыт в firewall хостера.
Amnezia не встаёт ни приложением, ни мастером
  → на VPS выполните:
        ls -l /dev/net/tun
        systemd-detect-virt
    файла нет или virt != kvm → тариф/хостер не подходит: включите «TUN/TAP»
    в панели хостера или берите другую ноду.
