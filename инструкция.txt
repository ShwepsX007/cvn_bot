ИНСТРУКЦИЯ: подготовка НОВОГО VPN-сервера к подключению к боту (“мастер установки”)
=====================================================================================

Тот же текст всегда висит в админке → “Серверы” → “🚀 Мастер установки” (правая колонка).

ФОН: сервер бота (192600) НЕ может подключаться к внешнему порту 22
    — у его хостера закрыт ИСХОДЯЩИЙ TCP/22. Поэтому SSH каждой ноды
    обязан слушать также порт 2222. Это единственная причина всех правок ниже.

ШАГ 1. Купите VPS: Ubuntu 22.04/24.04, KVM.
       Сохраните IP и root-пароль (приходят в панели хостера / на почту).

ШАГ 2. В панели хостера (firewall): откройте TCP 2222 для 0.0.0.0/0.
       Позже сюда же добавите UDP-порт Amnezia (шаг 6).

ШАГ 3. Включите второй SSH-порт 2222 (из VNC/веб-консоли хостера на самом VPS).
       Узнать, какой у вас вариант sshd:  systemctl status ssh.socket --no-pager

       Ubuntu 24.04 (socket-запуск sshd — порт держит systemd, Port в конфиге НЕ работает):
           mkdir -p /etc/systemd/system/ssh.socket.d
           cat > /etc/systemd/system/ssh.socket.d/listen.conf <<'EOF'
           [Socket]
           ListenStream=
           ListenStream=22
           ListenStream=2222
           EOF
           systemctl daemon-reload
           systemctl restart ssh.socket

       Ubuntu 22.04 и старее (обычный sshd):
           echo -e "Port 22\nPort 2222" >> /etc/ssh/sshd_config
           systemctl restart sshd

       Проверка:  ss -tlnp | grep sshd     → слушаются ОБА порта 22 и 2222.
       С компьютера:  ssh root@IP -p 2222  → пускает.

ШАГ 4. Установите Amnezia официальным приложением со своего ПК
       (с вашего ПК порт 22 — доступен, это нормально):
       приложение → добавить сервер → IP / порт 22 / root / пароль → раздел
       AmneziaWG → “Установить”. Дождаться конца, создать в приложении
       тестового клиента, подключиться — убедиться, что VPN работает.

ШАГ 5. Запустите мастер (админка → Серверы → 🚀): IP, SSH-порт 2222, root-пароль.
       Мастер сам: докинет SSH-ключ бота, проверит здоровье контейнера
       (если контейнер “рестартит” — попробует починить с сохранением конфига),
       зальёт add_user.sh/remove_user.sh (+дочистит \r-переносы), занесёт сервер в базу.

ШАГ 6. Мастер в конце покажет внешний UDP-порт (напр. 40158/udp) —
       откройте его в firewall-панели хостера (UDP, 0.0.0.0/0). Без этого туннель
       пустой трафик не пропустит.

ШАГ 7. Проверка через бота: “Клиенты” → тестовый доступ на новый сервер →
       конфиг на телефон → включить. Всё — сервер в продаже.
       (Цена: либо в карточке сервера, либо глобальная из “Настроек”.)


РАСПОЗНАВАНИЕ ПРОБЛЕМ
---------------------
timed out на подключении
  → В мастере указан не 2222, или в панели хостера TCP 2222 не открыт для всех.
  → Исходящий 22 закрыт на стороне бота НАВСЕГДА — порт 22 в мастере не использовать.
unable to connect к 2222
  → sshd на 2222 не слушает: шаг 3 не выполнен (или VPS переустановили — слетит
    и sshd_config, и dropin ssh.socket: повторите шаг 3 заново).
REMOTE HOST IDENTIFICATION HAS CHANGED
  → Норма после переустановки VPS (host-ключи новые). С ПК:
        ssh-keygen -R <IP>
        ssh-keygen -R "[<IP>]:2222"     # если то же самое для порта 2222
    затем ssh снова → ответить yes.
контейнер “is restarting”, логи пустые
  → сломан “заводской” контейнер хостера (нет awg0.conf): удалите контейнер
    и установите Amnezia приложением (шаг 4) — или дайте мастеру авто-ремонт.
мастер закончил ✅, но VPN не гоняет трафик
  → забыли шаг 6 (UDP-порт в firewall хостера) — самая частая причина.
Amnezia не встаёт ни приложением, ни мастером
  → не OpenVZ/LXC: на VPS выполните
        ls -l /dev/net/tun
        systemd-detect-virt
    файла нет или virt != kvm → партнер/тариф не подходит, включите “TUN/TAP”
    в панели хостера либо берите другую ноду.
