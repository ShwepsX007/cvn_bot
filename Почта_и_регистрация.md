# 📧 Регистрация и вход по почте (независимая, без Telegram)

## Что появилось

Сервис поддерживает **два равноправных канала входа** — по email с паролем и через
Telegram. **Регистрация по почте полностью самостоятельна**: подтвердив адрес, человек
сразу попадает в личный кабинет и может покупать/скачивать конфиги, ни разу не заходя
в телеграм-бота. И наоборот: зарегистрировавшись через Telegram, можно позже привязать
почту. Когда одно и то же пользуется и почтой, и Telegram, система объединяет их
в **один аккаунт**.

Как устроена идентификация:
- вся система ведет подписки/заказы/конфиги по внутреннему числовому ID;
- у «телеграмных» пользователей это их реальный `tg_id`;
- у чисто почтовых — внутренний **виртуальный ID** (`10^15 + id записи в email_accounts`),
  который никогда не совпадет с реальным Telegram ID;
- при привязке одной стороны к другой виртуальный аккаунт **объединяется** с реальным:
  подписки, заказы, заявки и почта переносятся на настоящий `tg_id`
  (`database.merge_virtual_into_real`), ничего не теряется и дублей не появляется.

Четыре способа связать почту и Telegram:

1. **Сайт → Telegram (добровольно).** Регистрация по почте → письмо с подтверждением →
   кабинет сразу доступен. В кабинете карточка «✈️ Telegram» с виджетом/кнопкой бота —
   при входе через Telegram почтовый аккаунт автоматически объединяется с ним.
2. **Сайт: вход по почте поверх телеграм-сессии.** Если в браузере уже вошли по почте,
   а затем вошли через виджет/ссылку бота — система видит ту же почту и объединяет аккаунты.
3. **Telegram → почта.** В боте кнопка «📧 Привязать почту» → пользователь отправляет
   email → письмо со ссылкой (2 часа) → переход по ней привязывает почту к tg.
   Если эта почта уже была зарегистрирована на сайте как самостоятельная (без Telegram) —
   аккаунты объединятся в один. Сразу на странице — форма «задать пароль».
4. **Из кабинета сайта** (вошёл через Telegram): карточка «📧 Почта» → ввести адрес →
   письмо со ссылкой-привязкой (так же с объединением, если почта была самостоятельной).

Остальное:
- Вход на сайте вкладкой «📧 Почта» (email + пароль). Неподтверждённая почта не пускает —
  при попытке входа письмо отправляется повторно.
- «Забыли пароль?» → письмо со ссылкой (1 час) → форма нового пароля.
- Регистрация защищена математической капчей (тот же `/api/captcha`, что у пробного доступа).
- Антибрутфорс: вход 8 попыток/10 мин с IP, регистрация и ссылки-привязки 5/час с IP.
- Почтовым аккаунтам без Telegram напоминания в TG не рассылаются (доставлять некуда) —
  их подписки живут по тем же срокам, конфигы скачиваются с сайта; админ видит в
  уведомлениях пометку «клиент без Telegram» и адрес почты.

## Архитектура

| Файл | Что делает |
|---|---|
| `emailauth.py` | нормализация/валидация email, scrypt-хэши паролей (только stdlib!), одноразовые токены, rate-лимитеры |
| `mailer.py` | отправка писем; транспорты **smtp** и **resend**; режим `auto` сам выбирает; тёмный HTML-шаблон письма |
| `database.py` | таблицы `email_accounts` / `email_tokens`; виртуальные ID почтовых аккаунтов (`VIRTUAL_TG_BASE`, `ensure_email_account_tg`) и объединение аккаунтов (`merge_virtual_into_real`) |
| `web_app.py` | роуты `/auth/email/register|login|verify|forgot|reset|link`, `/web/link_email`; кабинет работает и для почтовых аккаунтов (карточка привязки Telegram — опциональна) |
| `user_handlers.py` | кнопка «📧 Привязать почту» + диалог (с объединением самостоятельных почтовых аккаунтов) |
| `bot.py` | напоминания об окончании: почтовые аккаунты без TG помечаются без попытки отправки |
| `admin_panel.py` | рассылка пропускает аккаунты без Telegram; настройка `mail_*` |
| `templates/login.html` | вкладки Telegram / Почта (логин + регистрация + «забыли пароль») |
| `templates/auth_email.html` | страницы из писем: подтверждение, сброс, привязка, невалидная ссылка |
| `templates/dashboard.html` | кабинет: карточка «✈️ Telegram» (для почтовых) и «📧 Почта» (для телеграмных) |

Новых pip-зависимостей **нет** (smtplib / hashlib.scrypt / urllib — стандартная библиотека).

## Настройка почты (админ-бот → ⚙️ Настройки)

Раздел «📧 Отправка писем»:

- **📧 Тип отправки почты** — цикл `auto → smtp → resend → off → auto`.
  В `auto` берётся Resend, если задан ключ, иначе SMTP, если задан хост.
- **SMTP:** хост / порт (587=starttls, 465=ssl) / логин / пароль / TLS / отправитель.
- **Resend:** API-ключ (`re_...`) и отправитель. Рекомендуется, если на VPS закрыты исходящие SMTP-порты.
- «-» (минус) вместо значения очищает поле.

Пример для Yandex: хост `smtp.yandex.ru`, порт `587`, TLS `starttls`,
логин/пароль — от почтового ящика, From `Сервис AmneziaWG <vashmailbox@yandex.ru>`.

Важно: ссылки в письмах строятся от настройки **🌐 Адрес сайта** — она должна быть
`https://amneziawg.fun` (уже задана).

## Деплой (новый сервер 192600, /root/vpn_bot/)

1. Залить по FTP файлы:
   `mailer.py`, `emailauth.py`, `database.py`, `web_app.py`, `user_handlers.py`,
   `bot.py`, `admin_panel.py`,
   `templates/login.html`, `templates/auth_email.html`, `templates/dashboard.html`;
   `templates/link_telegram.html` больше не используется (можно удалить на сервере).
2. Установить пакеты **не требуется** (всё на stdlib).
3. Перезапуск: `systemctl restart vpn_bot` — схема БД не менялась, миграция не нужна.
   Уже существующие подтвержденные почты без привязки при следующем входе сами
   получат внутренний виртуальный ID и попадут в кабинет.
4. `/admin` → ⚙️ Настройки → задать SMTP или Resend → строка «📧 Отправка писем» перестанет говорить «не настроена».
5. Проверка: /login → вкладка «Почта» → регистрация → письмо пришло → подтверждение →
   сразу открывается личный кабинет (без требования Telegram) → покупка/скачивание конфига.

Если почта не настроена (`mail_mode=off`), бот в диалоге привязки честно отвечает «недоступно»,
а регистрация на сайте вернёт «Не удалось отправить письмо» — ничего не падает.

## Как это сделано в Licvid (для справки)

В Licvid основной способ входа сразу почта+пароль, Telegram — резервный, привязываемый из кабинета.
Почтовая отправка там — SMTP из env-переменных, а если VPS блокирует SMTP-порты — HTTPS API
(Resend по умолчанию, опционально SendPulse). Хэши — тот же scrypt (N=16384, r=8, p=1), TTL токенов
verify 24ч / reset 1ч / link 2ч — эти параметры перенесены один в один.
Отличие нашего порта: в Licvid аккаунт — отдельный uid; у нас почтовый аккаунт без
Telegram живет под внутренним виртуальным ID (`VIRTUAL_TG_BASE + id`), а при привязке
Telegram «схлопывается» в реальный `tg_id` — подписки/заказы/уведомления остаются
едиными и дубли-аккаунтов не появляется.
