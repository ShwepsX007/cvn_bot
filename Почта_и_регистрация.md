# 📧 Регистрация и вход по почте (как в Licvid, но в обе стороны)

## Что появилось

Сервис теперь поддерживает **второй канал входа** — по email и паролю, в дополнение к Telegram-виджету.
Оба канала ведут в **один и тот же аккаунт**: вся система по-прежнему опознаёт пользователя по `tg_id`,
почта — это просто «логин», который маппится на этот `tg_id`.

Три способа связать почту и Telegram:

1. **Сайт → Telegram.** Регистрация на сайте по почте и паролю → письмо с подтверждением →
   кабинет просит привязать Telegram виджетом → почта автоматически привязывается к tg.
2. **Telegram → почта.** В боте кнопка «📧 Привязать почту» → пользователь отправляет email →
   письмо со ссылкой (2 часа) → переход по ней привязывает почту к tg.
   Сразу на странице — форма «задать пароль» (свежий reset-токен, без второго письма).
3. **Из кабинета сайта** (уже вошёл через Telegram): карточка «📧 Почта» → ввести адрес →
   письмо со ссылкой-привязкой.

Остальное:
- Вход на сайте вкладкой «📧 Почта» (email + пароль). Неподтверждённая почта не пускает —
  при попытке входа письмо отправляется повторно.
- «Забыли пароль?» → письмо со ссылкой (1 час) → форма нового пароля.
- Регистрация защищена математической капчей (тот же `/api/captcha`, что у пробного доступа).
- Антибрутфорс: вход 8 попыток/10 мин с IP, регистрация и ссылки-привязки 5/час с IP.

## Архитектура

| Файл | Что делает |
|---|---|
| `emailauth.py` | нормализация/валидация email, scrypt-хэши паролей (только stdlib!), одноразовые токены, rate-лимитеры |
| `mailer.py` | отправка писем; транспорты **smtp** (любой: Yandex/Mail.ru/Gmail app password) и **resend** (HTTPS API, когда хостер режет SMTP-порты); режим `auto` сам выбирает; тёмный HTML-шаблон письма |
| `database.py` | таблицы `email_accounts` (почта↔tg_id, хэш пароля, флаг verified) и `email_tokens` (verify/reset/link со сроком действия); настройки `mail_*` |
| `web_app.py` | роуты `/auth/email/register|login|verify|forgot|reset|link`, `/web/link_email`; кабинет умеет email-сессию и авто-привязку в `/auth/telegram` |
| `user_handlers.py` | кнопка «📧 Привязать почту» + диалог |
| `admin_panel.py` | статус доставки и 8 кнопок настройки `mail_*` |
| `templates/login.html` | вкладки Telegram / Почта (логин + регистрация + «забыли пароль») |
| `templates/auth_email.html` | страницы из писем: подтверждение, сброс, привязка, невалидная ссылка |
| `templates/link_telegram.html` | экран «привяжите Telegram» для тех, кто вошёл только по почте |
| `templates/dashboard.html` | карточка «📧 Почта» |

Новых pip-зависимостей **нет** (smtplib / hashlib.scrypt / urllib — стандартная библиотека).

## Настройка почты (админ-бот → ⚙️ Настройки)

Раздел «📧 Отправка писем»:

- **📧 Тип отправки почты** — цикл `auto → smtp → resend → off → auto`.
  В `auto` берётся Resend, если задан ключ, иначе SMTP, если задан хост.
- **SMTP:** хост / порт (587=starttls, 465=ssl) / логин / пароль / TLS / отправитель.
- **Resend:** API-ключ (`re_...`) и отправитель. Рекомендуется, если на VPS закрыты исходящие SMTP-порты.
- «-» (минус) вместо значения очищает поле.

Пример для Yandex: хост `smtp.yandex.ru`, порт `587`, TLS `starttls`,
логин/пароль — от почтового ящика, From `AmneziaWG VPN <vashmailbox@yandex.ru>`.

Важно: ссылки в письмах строятся от настройки **🌐 Адрес сайта** — она должна быть
`https://amneziawg.fun` (уже задана).

## Деплой (новый сервер 192600, /root/vpn_bot/)

1. Залить по FTP файлы:
   `mailer.py`, `emailauth.py`, `database.py`, `web_app.py`, `user_handlers.py`, `admin_panel.py`,
   `templates/login.html`, `templates/auth_email.html`, `templates/link_telegram.html`, `templates/dashboard.html`
2. Установить пакеты **не требуется** (всё на stdlib).
3. Перезапуск: `systemctl restart vpn_bot` — таблицы создадутся сами при старте (миграция добавлена в `init_db`).
4. `/admin` → ⚙️ Настройки → задать SMTP или Resend → строка «📧 Отправка писем» перестанет говорить «не настроена».
5. Проверка: /login → вкладка «Почта» → регистрация → письмо пришло → подтверждение → кабинет просит привязать Telegram.

Если почта не настроена (`mail_mode=off`), бот в диалоге привязки честно отвечает «недоступно»,
а регистрация на сайте вернёт «Не удалось отправить письмо» — ничего не падает.

## Как это сделано в Licvid (для справки)

В Licvid основной способ входа сразу почта+пароль, Telegram — резервный, привязываемый из кабинета.
Почтовая отправка там — SMTP из env-переменных, а если VPS блокирует SMTP-порты — HTTPS API
(Resend по умолчанию, опционально SendPulse). Хэши — тот же scrypt (N=16384, r=8, p=1), TTL токенов
verify 24ч / reset 1ч / link 2ч — эти параметры перенесены один в один.
Отличие нашего порта: в Licvid аккаунт — отдельный uid, у нас же почта маппится на существующий `tg_id`,
поэтому подписки/заказы/уведомления остаются едиными и дубли-аккаунтов не появляется.
